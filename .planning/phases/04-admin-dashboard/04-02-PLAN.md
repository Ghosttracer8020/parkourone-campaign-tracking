<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser JS → admin-ajax.php (wp_ajax_pot_metrics) | The client posts preset/from/to + nonce; the server (Plan 01) re-validates everything — the JS is not a trust boundary by itself |
| server response → #pot-metrics-body innerHTML | The JS inserts server-built row HTML into the DOM |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-06 | Tampering/Spoofing | AJAX request from the client | mitigate | The nonce from potDashboard is sent under the 'nonce' key and verified server-side by check_ajax_referer('pot_metrics','nonce') (Plan 01); the client cannot bypass the manage_options check |
| T-04-07 | Information disclosure (DOM XSS) | #pot-metrics-body innerHTML swap | mitigate | The JS inserts ONLY the prebuilt row markup the server already escaped (esc_html/esc_attr in Plan 01); the client does not template or interpolate raw campaign strings itself, so no new injection sink is introduced |
| T-04-SC | Tampering | npm/pip/cargo installs | accept | No package installs — vanilla jQuery (already enqueued by WP core) + plain CSS, no build step, no new dependencies; nothing to audit |
</threat_model>
