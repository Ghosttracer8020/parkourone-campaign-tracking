<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → admin-ajax.php (wp_ajax_pot_metrics) | Authenticated admin request carrying preset/from/to + nonce; untrusted input crosses here |
| DB rows (campaign/landing strings) → rendered HTML | Stored event strings (campaign names) flow into the admin table; untrusted-at-rest content crosses into the DOM |
| GET query params on the dashboard page → server render | from/to/preset on initial page load are user-controlled |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Spoofing/Elevation | wp_ajax_pot_metrics handler | mitigate | check_ajax_referer('pot_metrics','nonce') + current_user_can('manage_options') before any work; register only wp_ajax_ (no nopriv) so anonymous callers are rejected by WP |
| T-04-02 | Tampering | preset/from/to params (GET render + AJAX POST) | mitigate | sanitize_key on preset; from/to validated against /^\d{4}-\d{2}-\d{2}$/; enforce from<=to; cap span ≤366 days; clamp future dates — invalid input cannot reach the gateway as raw SQL (POT_Store uses $wpdb->prepare regardless) |
| T-04-03 | Information disclosure | reflected campaign/landing strings in the table (XSS) | mitigate | esc_html() every text/count cell, esc_attr() every attribute (incl. the dashicons-warning title), counts through number_format_i18n() then esc_html — both the server render and the AJAX-built rows use the same escaped builder |
| T-04-04 | Information disclosure | dashboard page + metrics endpoint | mitigate | manage_options re-checked in render_page() and ajax_metrics(); page registered with manage_options cap; no metrics returned to non-admins |
| T-04-05 | Repudiation/DoS | oversized custom date range | mitigate | 366-day span cap + future clamp bound the query window the gateway sees |
| T-04-SC | Tampering | npm/pip/cargo installs | accept | No package installs in this phase — pure PHP + vanilla JS, no build step, no new dependencies (per CONTEXT: no external libs); nothing to audit |
</threat_model>
