<objective>
Retire the legacy theme analytics tracker in the SAME phase as client capture so exactly ONE tracker runs — no gap, no double-count. The theme (`Input/parkourone-theme`) is a SEPARATE repo and MUST NOT be edited; instead the plugin dequeues the theme's `po-analytics-tracker` script and removes the theme's server-side fallback pageview writer, all gated behind a toggleable option.

Purpose: Closes Pitfall 1 (double-counting). The new plugin tracker (Plan 01) and the theme tracker both gate on the same `window.poConsent.categories.analytics`, so without this cutover every CTA click is counted twice. Dequeueing `po-analytics-tracker` stops ALL theme JS-driven writes because the theme's `handle_track` REST route has no other caller; removing `track_basic_pageview` silences the wp_footer server-fallback for non-consenting visitors.

Output: `includes/class-pot-theme-retirement.php`, wired from `pot_init()` with require_once added (github-updater stays last). The runtime parity comparison (MIGRATE-02) is a DEFERRED MANUAL CHECKLIST item — the code ships the cutover; the operator runs the shadow-window parity check on staging before flipping live.
</objective>
