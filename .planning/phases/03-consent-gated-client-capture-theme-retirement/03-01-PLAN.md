<objective>
Capture the top two funnel stages — landing-page VISITS and "Probetraining buchen" CTA CLICKS — client-side, behind consent/admin/bot gates, written through `POT_Store` via a new dynamic REST ingest route (`POST pot/v1/event`). <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → REST `pot/v1/event` | Untrusted anonymous front-end POST crosses into the plugin and the events store |
| pot_attribution cookie → beacon payload | Client-controlled cookie value is echoed into campaign/source/medium fields |
| theme consent global → tracker | `window.poConsent` is read client-side to gate all device storage/network |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Spoofing/Elevation | `pot/v1/event` permission_callback | mitigate | Real WP-REST nonce check (`wp_verify_nonce($nonce,'wp_rest')`), header `X-WP-Nonce` then `_wpnonce` body fallback; never `__return_true`. Documented residual: anonymous front-end nonces are weak (public `wp_create_nonce` for non-logged-in users) but are the standard CSRF/abuse gate for a fire-and-forget beacon — accepted for v1; the handler does only one minimal indexed insert (no heavy work, Pitfall 11). |
| T-03-02 | Tampering/Injection | `handle_event` field sanitization | mitigate | `sanitize_text_field` + length-cap on campaign/source/medium; `esc_url_raw`+cap (path-only) on landing_path; alnum-only + cap on session_id; `type` constrained to {visit,click} via validate_callback. POT_Store writes via `$wpdb->insert` with explicit formats (parameterized) — no SQL concatenation. |
| T-03-03 | Information Disclosure (DSGVO) | events store columns | mitigate | NEVER store `$_SERVER['REMOTE_ADDR']` / IP or full UA — bot decision is a boolean only. All device storage (beacon, pot_sid) is gated behind `window.poConsent.categories.analytics` (TTDSG §25). Admins excluded at three layers. |
| T-03-04 | Denial of Service | unauthenticated ingest abuse | accept | Beacon route is low-value and does a single minimal insert; bot UA denylist + nonce gate raise the bar. No rate-limiting in v1 (aggregate-only data, no PII, low-value target). Revisit only if abuse observed. |
| T-03-05 | Stored XSS (deferred display) | landing_path / campaign stored values | mitigate | Stored sanitized (path-only, text-field). Output-escaping is the responsibility of the Phase 4 dashboard (`esc_html`) and Phase 5 API (JSON-encoded) — flagged here so the consumer escapes on display. |
| T-03-SC | Tampering | npm/pip/cargo installs | n/a | No package-manager installs in this phase — only first-party PHP/JS files. No package legitimacy gate required. |
</threat_model>
